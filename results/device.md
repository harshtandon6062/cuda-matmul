## Theoretical peaks

```text
Peak FP32 = SMs x FP32 lanes per SM x 2 FLOP per FMA x SM clock
          = 20 x 128 x 2 x 1.492 GHz
          = 7639.0 GFLOPS

Peak DRAM bandwidth = 2 transfers per clock (double data rate) x memory clock x bus width / 8
                    = 2 x 7.001 GHz x 96 bits / 8
                    = 168.0 GB/s

Ridge point = peak FP32 / peak bandwidth = 45.5 FLOP per byte
```

A kernel that does fewer than ~45 floating-point operations per byte it moves to or from DRAM cannot reach the FP32 peak on this GPU: it is **memory-bound**. Above that it can be **compute-bound**.

The same formula at the NVML maximum clock (2100 MHz) gives 10752.0 GFLOPS. That is a ceiling the GPU reaches only briefly when power and temperature allow. This project quotes "% of peak" against the 7639.0 GFLOPS figure above.

| FP32 FMA loop in registers (no memory traffic) | 7353.3 GFLOPS | 96.3% |

SM clock read by NVML while the FMA loop ran: **1492 MHz**. If every FP32 lane completed one FMA per cycle, the measured rate would correspond to a 1436 MHz clock (measured GFLOPS / (2 x 2560 lanes)).

Laptop GPUs run above or below the reported clock depending on power and temperature, so measured throughput can differ from the formula in either direction.
